## D-001 JUCE バージョン
- **JUCE 9.0.6**（`654bdbc7a9db0dae90849b44abe91f339e9f0768`）に固定。2026-11-21 時点の 9 系最新タグ。
- 経緯: 当初は SPEC v0.2 の「JUCE 8 系」に従い 8.0.17-security（`dabd5ad1`）で Phase 0 を完成させた。同日、ユーザーの指示で JUCE 9 へ変更し、SPEC §1 を v0.4 として改訂。
- 移行結果: ソースコードの変更は不要。macOS 26.7.3 / Xcode 27.2 / CMake 4.4.5 / Apple Silicon で Debug・Release ビルド、全ユニットテスト、auval、pluginval（strictness 5、VST3/AU）に合格。
- JUCE 9 の破壊的変更（`BREAKING_CHANGES.md`）のうち、今後のフェーズで関係するもの:
  - `Drawable` が `Component` を継承しなくなり、`Drawable::createFromSVG (const XmlElement&)` が削除された → Phase 5 で UI に SVG ロゴを組み込む際は JUCE 9 の API に従う。
  - `XmlDocument` / `ValueTree::readFromStream` / `JSON::parse` が、過度にネストした入力や不正データを拒否するよう強化された → 状態復元・プリセット読込（Phase 5）の破損耐性と同じ方向。拒否された場合に既定値へ安全に落ちることをテストで確認する。
  - `AlertWindow` / `MessageBoxOptions` / `NativeMessageBox` の API 変更 → プリセットの保存・削除確認ダイアログ（Phase 5）で新 API を使う。
  - `ThreadPool::addJob` のオーバーロード整理 → バックグラウンド処理を使う場合に注意。
- JUCE 9 の API はフェーズごとに同梱ドキュメントとヘッダーで確認してから使う（8 系の知識を前提にしない）。

## D-016 SuperSAW の扱い（暫定）
- SPEC §4.1 は SuperSAW を「Saw 群の重ね合わせ。既定 7 本」、§4.2 は「SuperSAW の 7 本は同一 OSC の Unison Voices = 7 を意味し、別の内部 7 倍ユニゾンを掛けない」と規定している。
- そのため **DSP 上は Saw と SuperSAW を同一**とし、違いは「選んだときのユニゾン本数の既定（7 本）」だけとした。ユニゾンは Noise 以外の全波形で有効。
- パラメーターの既定値は 1 つしか持てないので `osc.*.unisonVoices` の既定は 1。**SuperSAW を選んだときに 7 本・Detune 35 % にする動作は UI（Phase 5）で実装する。** それまでは汎用エディターで Unison Voices を手動で 7 にする必要がある。
- ホストオートメーションで Wave だけを切り替えた場合に、プラグイン側が別パラメーターを書き換えることはしない（オートメーションとの不整合を避けるため）。
- SuperSAW 専用の音作り（センター声の重み付け、専用 Detune カーブ、ハイパス等）は、Phase 2 以降の AB 試聴で必要と判断した場合に追加する（SPEC §18-3）。

## D-017 ユニゾンの設計（暫定、試聴で調整）
- **Detune 量**: `maxCents = 100 × (0.25·d + 0.75·d²)`（d = 0..1）。100 % で最外声 ±100 cent、既定 35 % で約 ±18 cent。
- **分布**: 左右対称。奇数本は中央の 1 声がデチューン 0（ピッチの芯）。対 k（1..K）のデチューンは `maxCents × (k/K)^1.5`。等間隔を避け、うなりの周期がそろわないようにした。
- **パン**: 対ごとに低い側と高い側を左右へ振り分け、対が外側へ行くほど広げる（`spread × k/K`）。対ごとに左右を入れ替え、高音側が片方に寄らないようにした。等パワーパン。Spread 0 では全声がセンター。
- **位相**: Retrigger は声 0 が位相 0、他は黄金比で散らした固定位相（全声同位相による過大なアタックピークを避けつつ、毎回同じ波形になる）。Free はボイスごとの乱数初期位相で走り続ける。
- **Noise**: 音程・ユニゾン・Spread・Phase Mode の影響を受けない。ボイスごとに独立した乱数系列（センター定位）。

## D-018 レベル設計（暫定、試聴で調整）
- 単音の内部ゲイン `Voice::voiceGain = 0.18`（約 -15 dB）。等パワーパンのセンター（-3 dB）と合わせ、単音 Saw のピークは片チャンネル約 -18 dBFS。
- ユニゾンは `1/√N` でパワー一定に正規化。実測で 1〜9 本のレベル差は ±0.15 dB 以内。
- **ボイス数による自動ゲイン調整は行わない**（和音の音数で音量が揺れるのを避ける）。実測: 6 音 SuperSAW ×7（ベロシティ 0.8）のピークは -5.0 dBFS。
- 出力の最終段に安全用ソフトリミッター: |x| ≤ 0.8（-1.9 dBFS）では完全に線形、それ以上を tanh で丸め、±1.0 を超えない。常時コンプレッションにはならない（SPEC §14.2）。16 音を強く弾いた場合や Output Gain を上げた場合にのみ掛かる。
- OSC Level は線形振幅。Velocity → Amp も Phase 1 では線形固定（量の調整は Phase 2 の `amp.velocity`）。
- Phase 4 で FX チェーンが入るとき、リミッターの位置（FX の後）を再設計する。

## D-019 ボイス処理の 2x オーバーサンプリング
- 経緯: 2 点 PolyBLEP 単体（等倍）では、可聴帯域（16 kHz 以下）の折り返し成分が Saw で -43.5 dB（D#6）/ -34.8 dB（C8）と測定された。SuperSAW を主役とする製品としては不十分と判断した。
- 採用: **ホストのレートが 70 kHz 未満（44.1 / 48 kHz）のとき、ボイス処理（発振器・エンベロープ、Phase 2 でフィルターも）を 2 倍のレートで実行**し、ポリフェーズ・オールパス IIR ハーフバンドフィルター（係数 8 個）で元のレートへ戻す。88.2 / 96 kHz 以上は等倍。
- 効果（実測、A4〜C8 の最悪値、16 kHz 以下の非倍音成分 / 基本波）:

  | 波形 | 44.1 kHz | 48 kHz | 96 kHz（等倍） |
  |---|---|---|---|
  | Saw | -56.5 dB | -59.4 dB | -60.5 dB |
  | Pulse 25 % | -53.5 dB | -62.5 dB | -62.1 dB |
  | Square | -59.7 dB | -62.6 dB | -62.1 dB |
  | Triangle | -89.4 dB | -94.3 dB | -93.9 dB |

- デシメーションフィルター（設計を数値検証済み）: 通過域（〜20 kHz @ 44.1 kHz）の偏差 0.002 dB 以下（実測）、阻止域 -104 dB。
- **レイテンシー**: IIR のため低域で約 1.8 サンプルの群遅延がある。整数サンプルではなく微小なため、**ホストへのレイテンシー申告は行わない**。Phase 4 の Drive（線形位相オーバーサンプリングを使う場合）で申告が必要になったら合わせて見直す。
- 全ボイス停止後 256 サンプルでフィルター状態をリセットし、出力を完全な 0 にする（デノーマルと不要な CPU 消費を避ける）。
- CPU コストは下記の実測に含まれる。SPEC §14.3「重ければエンジンの最適化を優先し、仕様値をむやみに下げない」に従い、今後重くなった場合は発振器の最適化（Sine のテーブル化、SIMD）で対応する。

## D-020 Amp ADSR（暫定）
- Attack: 指定時間で 0→1 の線形。Decay: 指定時間で Sustain との差が -60 dB になる指数カーブ。Release: 指定時間で -60 dB になる指数カーブで、-100 dB を下回った時点でボイスを解放する。
- 範囲は SPEC §7.1 の `[暫定]` どおり（A 0.1 ms〜10 s、D 1 ms〜10 s、S 0〜100 %、R 1 ms〜20 s）。ノブは対数的な操作感になるようスキューを付けた（中央値 A 100 ms / D 300 ms / R 400 ms）。
- 既定値: A 2 ms、D 300 ms、S 80 %、R 200 ms（SPEC に規定なし）。
- エンベロープの状態は double で保持する（float では長い Decay で Sustain の手前に止まる不具合を実測で確認したため）。

## D-021 ボイス管理
- 16 ボイス固定。同音の重複 Note On は別ボイスとして発音し、Note Off 1 回につき「その音を押さえている最古のボイス」1 つだけを離す。
- スティールの優先順位は SPEC §3 どおり: 空き → Release 中で最もエンベロープの小さいボイス → 最古のボイス。
- スティール時は奪われるボイスを 2 ms の線形フェードで消してから新しいノートを開始する（発音が最大 2 ms 遅れる）。フェード中に離鍵されたノートは、開始直後に Release へ進む。
- CC64 ≥ 64 でサステイン。CC123（All Notes Off）はペダルの状態にかかわらず全ボイスを Release へ、CC120（All Sound Off）は 2 ms フェードで即時消音。
- `prepareToPlay` / `releaseResources` で全ボイスをリセットする。

## D-024 フィルター: 3 キャラクターの中身（Phase 2、暫定）
SPEC §6.1 の方針どおり、同じ TPT / SVF コア（Simper 形式、2 段まで）を使い、キャラクターごとに非線形・音量補正・応答を変えた。名前だけ違って中身が同じにならないよう、差を自動テストで検査している（`tests/dsp/FilterTests.cpp`）。

| | Analog | Clean | Punch |
|---|---|---|---|
| コア | 帯域通過側の積分器を tanh で飽和（レベル 10） | 線形 | 線形 |
| 入力段 | 常に軽い tanh 飽和（レベル 3） | Drive 0 では完全に素通し。Drive > 0 で tanh（レベル 2.5） | Drive > 0 で tanh（レベル 2） |
| 出力段 | なし | なし | 3 次ソフトクリップ（上限 1.5） |
| レゾナンス 100 % の Q | 10 | 14 | 8 |
| レゾナンスの音量補正（指数） | 0.30 | 0.20 | 0.55 |
| カットオフの追従 | 1.5 ms の遅れ | 遅れなし | 遅れなし |

- 実測（LP12、入力 0.5、レゾナンス 100 % のピークゲイン）: Clean +17.7 dB、Analog +5.3 dB、Punch +6.0 dB。同じパッチでの出力の差は RMS で −21〜−12 dB（−30 dB 以上を合格条件にしている）。
- **モード**: LP12 / LP24 / HP12 / HP24 / BP12。24 dB は 2 段で、レゾナンス 0 では 4 次 Butterworth（Q = 0.541 / 1.307）。レゾナンスは 2 段目だけに持たせる。Q はノブに対して指数カーブ。
- **Cutoff**: 20 Hz〜20 kHz、かつ内部レートの 0.45 倍以下にクランプ。係数は `tan` でプリワープし、44.1〜192 kHz で −3 dB 点が一致することを検査。
- **Drive**: 入力ゲイン 0〜+24 dB（dB で線形）。音量補正は `preGain^-0.6`。
- **スムージング**: Cutoff（対数領域）・Resonance・Drive・Env Amount は 5 ms。各ボイスのカットオフはコントロール周期（内部 32 サンプル）ごとに目標を決め、その間は係数をサンプル単位で線形補間する。
- **安定性**: 線形 TPT は係数を変調しても安定。Analog の飽和はエネルギーを減らす方向にしか働かない。レゾナンス・Drive 最大で、32 サンプルごとにカットオフを 20 Hz〜20 kHz の乱数に飛ばしても有界（テスト）。状態が非有限になったらリセットする。
- **既定値**: Character = Analog（選択肢の先頭）、Mode = LP24、Cutoff = 20 kHz（全開）、Resonance / Drive = 0。DSP 構造体（`EngineParams`）の既定は Clean で、発振器単体のテストが飽和の影響を受けないようにしている。
- **制限**: Character / Mode を発音中に切り替えると、タップと非線形が瞬時に変わるため小さなクリックが出ることがある（クロスフェード未実装）。Analog / Drive の飽和による折り返しは未計測（ボイス処理は 2x オーバーサンプリング内にあるが、飽和専用の追加オーバーサンプリングはしていない）。聴感で問題があれば Phase 6 までに対処する。

## D-025 フィルターの変調レンジ（Phase 2、暫定）
- **Env Amount**: ±100 % = ±8 オクターブ。20 Hz〜20 kHz（約 10 オクターブ）のほぼ全域を動かせ、Brass で使う 3〜4 オクターブが 40〜50 % に来る。
- **Key Tracking**: 100 % でノート 60 を基準に 1:1。OSC の Octave / Semitone / Fine は含めない（鍵盤のノートだけに追従）。
- **Velocity → Cutoff**: `移動量 = −5 オクターブ × 量 × (1 − velocity)`。ベロシティ最大でノブの値どおり、弱く弾くほど暗くなる。カットオフのノブが「最も明るいとき」を表すので、音作りの見通しがよい。
- Filter EG の既定値: A 2 ms、D 300 ms、S 30 %、R 200 ms（SPEC に規定なし）。範囲とスキューは Amp ADSR と同じ。
- Filter EG は Note Off で Release に入る（Amp と同じタイミング）。

## D-026 Transient（Phase 2、暫定）
- 範囲は SPEC §5 の `[暫定]` どおり。既定値: OFF、Mode = Noise Burst、Amount 50 %、Duration 20 ms、Noise Color 50 %、Pitch Snap +12 st。
- **Amount** は Noise Burst の音量と Pitch Snap の深さの両方に掛かる（実効の Snap = Pitch Snap × Amount）。SPEC は Amount の対象を明記していないため、「Amount 0 = Transient なし」となる解釈を採った。
- **Duration**: 指数減衰で、Noise Burst は Duration で −60 dB、Pitch Snap は 1/1000 になる。Pitch Snap は Duration の 1.5 倍以降を厳密に 0 とする（収束後のピッチは誤差 0.03 % 未満をテスト）。
- **Noise Burst**: ボイスごとに独立した乱数。モノラル（センター）でボイスミックスに加え、フィルターと Amp を通す。ポップ防止に 0.5 ms のフェードイン。
- **Noise Color**: 0〜50 % は 1 次ローパス（300 Hz → 20 kHz）、50〜100 % は 1 次ハイパス（100 Hz → 8 kHz）。50 % がほぼホワイト。フィルターで失われる音量は dB で半分だけ補正する。
- **Pitch Snap**: OSC A/B 共通のピッチオフセット（各 OSC の Tune は保持）。コントロール周期ごとに閉じた式で求めるので、ブロック分割に依存しない。Noise 波形には効かない。
- Retrigger でも Noise Burst の乱数系列は毎回変わる（発振器の位相だけがそろう）。

## D-027 Velocity → Amp と Sustain 0 のボイス解放（Phase 2）
- `amp.velocity`（0〜100 %、既定 100 %）を追加。`gain = 1 − a + a × velocity`。100 % は Phase 1 の挙動（ベロシティに比例）と同じ。
- Amp の Sustain が 0 % のとき、Decay が −100 dB を下回った時点でエンベロープを停止し、鍵盤を押さえたままでもボイスを解放する。Stab を連打してもボイスが埋まらない。解放後に Sustain を上げても、その音は鳴り直さない。

## D-030 Pitch Bend / Vibrato（Phase 3、暫定）
- **Pitch Bend**: `performance.bendUp` / `bendDown`（0〜48 半音、整数、既定 2）と `bendMode`（Symmetric / Independent）。Symmetric では Bend Up の値を上下両方に使い、Bend Down の値は保持したまま無視する。
- 14 bit の MIDI 値は、8192 を中心に上側を 8191、下側を 8192 で割る。両端で厳密に ±1 になり、指定幅ちょうどに到達する（0 / 2 / 12 / 48 半音 × 3 レートで誤差 1 cent 未満をテスト）。
- スムージングは 5 ms（他のピッチ系と同じ）。OSC の Octave / Semitone / Fine との関係は保持する。MPE は非対応。
- **Vibrato**: LFO は正弦波で、位相は全ボイス共通（SPEC §7.5 `[暫定]`）。深さ = Depth × CC1。CC1 は 5 ms でスムージング。
- **Vibrato Delay**: ボイスごとにノートオンからの経過時間で判定する。Delay の間は 0、その後 **Delay の半分の時間**をかけて smoothstep で立ち上げる（SPEC は「なだらかに」とだけ規定）。Delay 0 では最初から有効。
- ピッチベンドとビブラート、Pitch Snap は半音 / cents の加算で合成する。ピッチの更新はコントロール周期（内部 32 サンプル）ごと。
- 既定値は SPEC どおり: Depth 35 cent、Rate 5.5 Hz、Delay 0 ms。

## D-031 Macro の実装（Phase 3）
- ホストパラメーターは `macro.1`〜`macro.4`（0〜100 %、既定 50 % = ニュートラル）。マクロ自身は割当先にできない。
- **Base / Effective**: APVTS が持つのは Base 値。オーディオスレッドがブロックごとに `Effective = clamp(Base + Σdelta)` を正規化空間で計算し、実値へ戻して DSP に渡す。合計が 0 のとき（全マクロがニュートラル）は Base 値をそのまま使い、変換の丸めも入れない。正規化は `params::toNormalised` / `fromNormalised`（APVTS と同じスキュー式。一致をテスト）。
- **割当の保持**: `MetaState`（メッセージスレッド側、内部ロックあり）がマクロ名・CC・割当（target / deltaMin / deltaMax / curve）を持つ。各マクロ最大 8 割当、対象は連続値のみ、同じ対象への再割当は上書き。カーブは Linear / Ease In / Ease Out。
- **オーディオスレッドへの受け渡し**: 計画ではポインタ交換としていたが、スナップショットが固定長の小さな POD（32 エントリ）なので、**スピンロック + オーディオ側は try-lock のみ**でコピーする方式にした。オーディオスレッドは待たず、取れなければ次のブロックで取り込む。確保・解放が一切発生しない。
- **スムージング**: マクロ値に 10 ms の一次スムージング（ブロック単位）。その先は各パラメーターのスムージングが効く。
- **MIDI CC**: 割当可能なのは CC2〜119（CC64 を除く）。CC を受けるとオーディオスレッドは即座にその値を使い、30 Hz のタイマーがメッセージスレッドでホストパラメーターへ反映する（オーディオスレッドからホストへ通知しない）。その後ホストや UI がマクロを動かせば、そちらが優先される。
- **MIDI Learn**: `beginMidiLearn(macro)` の後、最初に届いた割当可能な CC を割り当てる。1 つの CC は 1 つのマクロにだけ属する。CC 割当はプリセット単位（状態と一緒に保存）。
- **状態保存**: `<META><MACROS>` に保存。不正な割当（存在しない ID、離散値、非有限値）は読み飛ばし、範囲外はクランプ。META のない古い状態ではマクロを初期状態に戻す。`stateVersion` は 1 のまま（未公開）。
- UI 表示用に、マクロ適用後の実効値を `getEffectiveValue()` で読める。

## D-032 FX セクションの実装（Phase 4、暫定）
- **配置**: FX は `polybrisk_dsp` の `src/fx/`（JUCE 非依存）。`SynthEngine` がボイス合計（デシメーション後、ホスト側レート）に対して `FxChain` を実行し、その後に Output Gain → 安全用リミッターを置く。順序は Drive → Chorus → EQ → Imager → [Dry + Delay wet + Reverb wet]。
- **バイパス**: 各 FX の ON/OFF と一括バイパスは 10 ms のクロスフェード。OFF になり切った FX は内部状態を捨てる。Delay / Reverb は入力（センド）側にも同じフェードを掛ける。すべて OFF のときは完全な素通し（ビット一致）。
- **Mix の法則（Delay / Reverb）**: 2 つの並列 wet パスなので、Mix 50 % までは dry を保ったまま wet を上げ、50 % を超えると dry を下げる（100 % で wet のみ）。dry のゲインは両者の積。
- **無音の扱い**: 入力が無音で出力も −120 dB 未満の状態が続いたら（Delay 使用時 3 秒、Reverb のみ 0.6 秒、それ以外 0.25 秒）、内部状態を捨てて完全な無音にする。ホストへ申告する tail は 20 秒。
- **DRIVE**: プリゲイン 0〜+30 dB。カーブは Warm = tanh、Tape = atan（膝がゆるい）、Tube = 上下非対称の tanh（偶数次倍音、10 Hz の DC 除去つき）、Soft Clip = 3 次、Hard Clip = クランプ、Wavefold = 正弦の折り返し。機材のエミュレーションではない。Tone は 800 Hz〜20 kHz のローパス。Auto Gain は `preGain^-0.65`。
  - **オーバーサンプリングは 4x**（IIR ハーフバンド 2 段）。実測（5 kHz を Drive 80 % で歪ませたときの 20 kHz 未満の折り返し）: Warm −68.9 dB、Hard Clip −44.5 dB、Wavefold −91.6 dB。2x との比較計測はしていない（CPU に余裕があるため 4x 固定とした）。IIR のためレイテンシーはなく、ホストへの申告は 0。Mix を 100 % 未満にしたとき、高域で dry との位相差による色づきが出る可能性がある（未評価）。
- **CHORUS**: Classic は左右 1 タップ（12 ms、LFO 90° 差）、Wide は左右 3 タップ（8 / 14 / 20 ms、120° 間隔、左右逆相）。3 次エルミート補間。Rate が速いときは変調幅を自動で狭める。
- **EQ**: RBJ の式。Low Shelf 100 Hz、Mid Bell 200 Hz〜8 kHz（Q = 1）、High Shelf 8 kHz。周波数固定は SPEC の `[暫定]` どおり。
- **IMAGER**: Side だけを増減し、Mid には触れない。Width > 100 % では `1/sqrt((1+w²)/2)` で出力を補正。Mono Bass は Side に 150 Hz の 2 次ハイパス。
- **DELAY**: 最大 2.5 秒。同期音価は 1/4・1/8・1/16 とその付点・3 連（9 種）。テンポが得られない・不正な場合は 120 BPM。タイムの変更は 2 つの読み出し位置の 40 ms クロスフェード（ピッチの滑りなし）。フィードバック経路に Tone のローパスと 80 Hz のハイパス。Ping Pong は入力をモノラルで左へ入れ、左右に `sqrt(feedback)` ずつ掛けて跳ね返す。Ducking は入力のピーク追従（アタック 5 ms、リリース 250 ms）。
- **REVERB**: 自前の 8 ライン FDN（Householder）+ 直列オールパス 4 段の入力拡散 + Pre-delay。Room / Plate / Hall はディレイ長（11〜34 / 19〜50 / 41〜103 ms）、拡散、高域減衰、変調（Hall のみ）が異なる。実測（最初の 30 ms のエネルギー比）: Room 8.3 %、Plate 3.2 %、Hall 0.0 %。Decay は RT60 として ±30 % 以内で一致。Type / Size の変更は wet を 20 ms でフェードアウト → クリア → フェードイン。
- 既定値はすべて OFF。各パラメーターの既定値は `docs/PARAMETER_IDS.md`。

## D-034 RHYTHM: 共通クロック / Trance Gate / Arpeggiator（Phase 4.5）
追加仕様 `docs/ADDON_TRANCE_GATE_ARPEGGIATOR.md` の `[暫定]` と、仕様にない点の判断。

- **配置**: `src/rhythm/`（`polybrisk_dsp`、JUCE 非依存）。`SynthEngine` が `RhythmClock` / `TranceGate` / `Arpeggiator` を持つ。ホスト情報は `PluginProcessor` が `juce::AudioPlayHead::getPosition()` から読み、POD の `TransportInfo`（BPM・再生状態・PPQ）として渡す。
- **クラス構成**: 追加仕様 §8 の `ArpNoteScheduler` は独立したクラスにしていない。1 ステップ 1 ノートで、未発行の Note Off は常に 1 つなので、`Arpeggiator` が「発音中の Note ID と Note Off 位置」を持つだけで足りる。`GatePattern` は 32 要素固定の POD。
- **クロック**: 位置の単位は拍（PPQ）。ホストが再生中で PPQ が有効ならホスト位置が正本（ブロックごとに取り込み、ブロック内はテンポで進める）。それ以外は内部クロックで進み続ける。テンポが不明・不正なら 120 BPM。位置のジャンプ（ループ・シーク）と、ホスト駆動 ⇄ 内部クロックの切り替わりを「不連続」として扱う。
- **境界の判定**: 積算した位置が境界のごく手前に来て 1 サンプル遅れるのを防ぐため、判定に 1e-9 拍の許容を入れた。これで 32〜2048 サンプルのどのブロック長でも同じ結果になる（テスト）。
- **Swing**: 追加仕様 §5.2 の式どおり（前 `T(1+k)`、後ろ `T(1−k)`、k = Swing/100）。
- **Trance Gate**:
  - Smooth は「その時間でおおむね（95 %）遷移し終える」1 次スムージング（時定数 = Smooth / 3）。既定 3 ms。
  - ON/OFF は 10 ms のクロスフェードで 1 倍との間を行き来する。リセット直後から ON の場合はフェードインせず、パターンの状態から始める。
  - FX の一括バイパスの対象外。RHYTHM 独立のバイパスは設けていない（`[暫定]` の「持たせてもよい」は採らず、`gate.enabled` / `arp.enabled` で足りると判断）。
  - Restart = Note On の起点は「何も押していない状態からの最初の Note On」。ホスト停止中は Restart の設定にかかわらず Note On 起点で動く。
  - パターンは 16 ステップで定義した 6 種（追加仕様 §3.3 の表どおり）。32 ステップでは 2 回繰り返し、8 ステップでは前半を使う。既定は「Pulse 16」。パターン選択時の Undo / 確認は UI（Phase 5）の課題。
- **Arpeggiator**:
  - Arp ON の間、元の Note On は発音させず、生成ノートだけを鳴らす。生成ノートは内部 Note ID で終了する（`SynthEngine` にノート ID 指定の Note Off を追加。D-023 の予定どおり）。Arp を ON にする前から鳴っていた直接のノートは、その Note Off で通常どおり離れる。
  - 発音順: Up / Down / Up-Down は音程順（同音は押した順）、As Played は押した順。Octaves は「1 オクターブ目を一巡 → 2 オクターブ目…」の順に展開し、127 を超える音はスキップ。Up-Down は両端を重ねない。
  - Random はステップ番号だけから決まるハッシュ（ブロック長や分割位置に依存しない）。
  - Restart = Note On（既定）: フレーズの最初の Note On の瞬間に 1 音目を鳴らす。押さえたままの追加では位相をリセットしない。Restart = Transport: ホストのグリッドに合わせ、ステップの途中で押さえた場合は次の境界まで待つ。発音順もタイムライン上のステップ番号に固定する。
  - Gate Length 100 % では、同じサンプルで Note Off → Note On の順に発行する。
  - **CC64**: Arp ON の間は和音の保持に使う（生成ノートをペダルで伸ばすことはしない）。Latch OFF でペダルを離すと、物理的に押していない鍵は消える。
  - **Latch**: 全部離しても最後の和音で続ける。何も押していない状態から新しく押すと、その時点で和音を置き換える（追加仕様は「次の適切なステップ境界で反映」としているが、置き換えは即時とし、次のステップから新しい和音が鳴る）。
  - **止まる条件**: 和音が空になった時点（Latch OFF で全部離す、Latch を外す、Arp を OFF にする、All Notes Off / All Sound Off / リセット）で、ステップ境界を待たずに Note Off を出す。
  - **ホスト停止**（`[暫定]`）: 生成ノートを終了し、Latch / ペダルで保持しているだけの和音は捨てる。押さえたままの鍵は内部クロックで続ける。**ループ・シーク**: 生成ノートを終了して新しい位置に同期する。
  - **MIDI チャンネル**（`[暫定]`）: チャンネルを区別せず、全チャンネルのノートを 1 つの和音として扱う（音源自体がチャンネルを区別していないため）。MPE 非対応。
  - 同時に押せる鍵は 32 まで（それ以上は無視）。
- **状態保存**: `gate.*` / `arp.*` は通常のパラメーター。Gate パターン・パターン名・編集フラグは `<META><RHYTHM>` に保存する。項目がなければ Gate / Arp とも OFF（既定値）、パターンは既定に戻る。押鍵・発音中のノート・クロックの位置・Latch の和音は保存しない。
- **トグル / セレクターのオートメーション**: ステップ境界での適用はしていない（Gate はクロスフェード、Arp は即時）。グリッチが問題になれば Phase 6 で対処する。
- 追加仕様 §11-7 のとおり、汎用シーケンサー・外部 MIDI 出力へは拡張していない。

## D-035 プリセットシステム（Phase 5）
- 形式は `docs/PRESET_SCHEMA.md`。JSON → 状態ツリー → `StateSerializer` の順で適用し、ホスト状態の復元と読込経路を統一した。
- Factory プリセットは `juce_add_binary_data` で組み込む。User プリセットは `~/Library/Application Support/POLYBRISK/Presets/User/`。お気に入りと Performance Lock は `settings.json`（プリセットファイルには含めない）。
- **Save**: User プリセットを開いているときは上書き、Factory / 未保存のときはブラウザーの Save As を開く。同名の User プリセットへ保存すると上書き（ID は引き継ぐ）。

- **プリセット切替時**: Arp の生成ノートを終了し、Latch の和音を捨てる。発音中のボイスと Delay / Reverb の尾はそのまま（パラメーターのスムージングで遷移する）。切替時のノイズの聴感確認は未実施。

## D-039 UI の見直しと Gate パターンの追加（2026-11-21、Standalone を見たユーザーの指摘による）

- **縦位置の統一**: 1 行に並ぶコントロールは、ラベルを上端、操作部の中心をノブの中心、値の表示を下端にそろえる（`ui::row`）。以前はボタンと選択だけ行の中央に寄せており、ラベルと操作部の高さがノブとずれていた。
- **ON/OFF はスイッチ**: テキストボタンをやめ、スライド式のスイッチ + `ON` / `OFF` の表示にした。電源のスイッチのラベルは `Power`。
- **エンベロープの図**: Filter Envelope と Amp Envelope に ADSR の形を表示する。表示のみで、編集はノブで行う。時間の区間の幅は実時間ではなくノブの位置（正規化値）に比例させる（1 ms と 10 s を同じ図に収めるため）。
- **Simple 表示**: マクロのノブを 128 px から 92 px に縮めた。RHYTHM は Trance Gate と Arpeggiator の 2 つのパネルに分け、左から詰めて並べる。コントロールは OFF のあいだも位置を変えず、薄く表示する（SPEC §9.1 を改訂）。
- **Gate パターン**: 6 → 45 種類（うち Fast 1/32 の 6 つは、ユーザーが示した他社シンセの画面にあった形を受けたもの。元の画面は 1/32 の速さだったので、選ぶと `gate.rate` を 1/32 にする。当初は 1/16 のまま「8th Mix」として収録していたが、テンポが半分になるため改めた。1 つは元が 1/64 だが、`gate.rate` に 1/64 はないので 1/32 としている）。追加仕様 §3.3 の 6 つは名前・順序・形を変えない。追加分は定番のリズム（ギャロップ、3+3+2、クラーベ、サイドチェイン風など）を形として起こしたもので、**試聴による選別はしていない**。プリセットはパターンの値そのものを保存しているので、既存プリセットとプロジェクトへの影響はない。

## D-040 Trance Gate のステレオ化とスイッチの形（2026-11-21、ユーザーの要望）

- **パラメーターを 2 つ追加**（110 → 112 個）: `gate.stereo`（ON/OFF、既定 OFF）、`gate.width`（0〜100 %、既定 100、マクロ割当可）。既存の ID・順序は変えていない。
- **パターンは左・右の 2 段**（`GatePattern::values` / `right`）。Stereo が OFF のあいだは左だけを使い、グリッドでの編集は左右の両方に同じ値を書く（あとで Stereo を ON にしても左右がそろった状態から始められる）。
- **Width の定義**: 各ステップで `both = max(L, R)` とし、`L' = both + (L − both) × width`（R も同様）。平均ではなく最大値に寄せるのは、Width を下げたときにリズムが消えず、定位だけが中央に寄るようにするため（左右交互のパターンを平均すると、常に半分の音量になってゲートの効果がなくなる）。
- **保存**: 状態・プリセットとも `gatePatternRight` を追加。左右が同じなら書かず、ない場合は左と同じとして読む。**既存の 64 プリセットと保存済みの状態は、そのまま Stereo OFF・同じ音で読める**（`stateVersion` / `schemaVersion` は 1 のまま）。
- **収録パターン**: Stereo グループ 7 つを追加（計 52）。ステレオのパターンを選ぶと UI が `gate.stereo` を ON にする。モノラルのパターンを選んでも OFF には戻さない（左右が同じなので音は変わらない）。
- **Gate は Imager の後**にあるため、Stereo Gate の左右の振り分けは Imager の Width / Mono Bass の影響を受けない。Delay / Reverb には振り分けた後の音が入る。
- **スイッチ**: 横スライド式から縦型（溝の中をキャップが上下し、上が ON、ON のキャップが発光色）に変えた。ユーザーが示した他社製品の縦型電源スイッチを方向性の参考にしたが、形・配色・表記は独自（I / O の刻印と別体の LED は使わず、キャップ自体の色と `ON` / `OFF` の表示で状態を示す）。

## D-041 LFO / Mono・Legato・グライド / Sub・Noise / アフタータッチ / Phaser・Flanger ほか（2026-11-21、ユーザーの指示）

「LFO はあった方がよいか」「ほかに要るものは」という相談への提案を、ユーザーが「全部入れて」と承認したもの。v0.2 で初期リリースの対象外としていた項目（Mono / Legato / Portamento、汎用 LFO）の一部を、範囲を絞って取り込む。SPEC は v0.9。

- **パラメーター 25 個を追加**（112 → 137）。既存の ID と意味は変えていない。`gate.rate` の選択肢は**末尾**に `1/64` を足した（途中に入れると保存済みのインデックスがずれるため）。
- **既存の音への影響はない**: 追加した機能の既定値（各深さ・レベル 0、Poly、Glide 0）では、出力は追加前とビット単位で一致する。64 プリセットのピークと平均音量が変更前と完全に同じであることを確認した。
- **LFO は 1 基・行き先は固定の 4 つ**（Cutoff / Pulse Width / Pitch / Amp）。SPEC の「複雑なモジュレーションマトリクスは不要」を守るため、行き先の追加と 2 基目は実装しない。
  - 値はコントロール周期（内部レートで 32 サンプル）ごとに更新する。Cutoff はその間を直線でつなぎ、Amp はサンプル単位でなだらかに追従させる。Pitch と Pulse Width は周期ごとの段差になる（Square / S&H では意図した動き。Sine などでは 0.3 ms 刻みで、ビブラートと同じ扱い）。
  - S&H は周期の番号から値を決める（状態を持たない）ので、ブロック分割やシークによらず同じ結果になる。
  - テンポ同期でホストが再生中のときは、位相を音楽位置から毎回求める（ループやシークの後もずれない）。
- **Mono / Legato**: 新しいボイスを取らず、鳴っているボイスの音程を移す。Mono の再始動はエンベロープを 0 に戻さず、いまのレベルから Attack をやり直す（クリックを避けるため）。Release 中の余韻は切らない（厳密な単音にはならないが、切ると段差が出る。聴いて判断する `[暫定]`）。
- **グライド**は半音単位で直線・一定時間。Poly でも直前のノートから滑らせる（和音では全声が同じ起点から動く）。
- **Sub** は OSC A / B の Tune に追従しない（OSC を 5 度や 1 オクターブにずらしても、Sub は弾いた音の下に居続ける）。
- **アフタータッチ**はチャンネル単位。Poly Aftertouch のメッセージも同じ 1 つの値として扱う（MPE・ノートごとの表現は対象外のまま）。
- **Phaser / Flanger** は 1 つの FX で Type を切り替える（FX は 7 種類）。位置は Drive の後・Chorus の前。Feedback は 0.9 までで、ループは常に安定する。
- **Gate のランダム**: 1 拍目の頭は必ず開け、開くステップは 6 割前後。Undo で戻せる。
- **UI**: 一括バイパス中は個々の FX のスイッチの色を落とし、`BYPASS` と表示する。プリセットのお気に入りは、行の左端の星をクリックして付け外しする（音色は切り替わらない。右側の Favorite ボタンは廃止）。Macros タブを開いたとき、名前欄が編集状態にならないようにした。
- **未確認**: どれも試聴していない。LFO の各行き先の効き方、グライドのカーブ、Phaser の掃引範囲（200 Hz〜4 kHz）、Sub / Noise のレベル感は、聴いてから調整する前提の初期値。
- **CPU**（Release、Apple M1 Max、48 kHz / 128 samples、DSP エンジン単体）: 16 音 × SuperSAW 7 × OSC A+B + Analog LP24 + FX 6 種の基準条件は平均 10.73 %（変更前 10.76 % と同じ）。そこへ LFO（4 つの行き先すべて）・Sub・Noise・Phaser を足すと平均 11.91 %、p99 379 µs（予算 2667 µs の 14 %）。この計測では単発のピークに 1.5〜2.7 ms が出たが、変更していないシナリオ（Saw ×9）でも出ており、Standalone を起動したままの計測による割り込みとみられる（静かな状態での再計測は未実施）。

## D-044 Trance Gate の既定を Rate 1/32 + Shifted Long に（2026-11-21、ユーザーの指示）

## D-055 Output Gain をプリセットから切り離し、Preset Level を追加（2026-11-22、ユーザーの指示）

これまで、音色ごとの音量の差は `output.gain` をプリセットごとに変えてそろえていた。ユーザーの指摘: OUT はユーザーが設定するものなので、プリセットで変えないでほしい。音色ごとの音量の差は、プリセット側で別に調整してほしい。

- **`output.gain`（画面上部の OUT）**: ユーザーが決める全体の音量。
  - プリセットの JSON に書かない。プリセットを読んでも、いまの値を必ず保持する（古いファイルに `output.gain` が入っていても無視する）。
  - 動かしても音色は Dirty（名前の横の `*`）にならない。
  - ホストの状態（DAW のプロジェクト、Standalone の設定）には保存する。ID・範囲・既定値は変えていない。
- **`preset.level`（新規、Preset Level）**: 音色ごとの音量の補正。−24〜+24 dB、既定 0 dB。プリセットに保存する。ほかの連続値と同じく、マクロの割当先にできる。Advanced の PERFORMANCE ページの「Preset」に Level のノブを置いた（これまで同じ場所にあった Output の Gain ノブは、上部の OUT と重複していたので外した）。
- 最終的な音量は 2 つの積。DSP は変えていない（エンジンに渡す出力ゲインを掛け合わせるだけ）。パラメーターは 139 → **140**。
- **Factory**: `tools/level_presets.py` が書く補正値を `preset.level` に入れるようにした。値は同じなので、OUT が 0 dB のときの音量はこれまでと変わらない。範囲が ±12 → ±24 dB に広がったので、上限に当たっていた **Arp Pulse Stab だけ +12.0 → +13.0 dB** になった（ほかの +12 dB の音色は、目標の音量かピークの上限に届いていて変わらない）。
- **互換性**: Factory はまだ配布していない。開発中に保存した User プリセットは、入っていた `output.gain` が無視され、Preset Level が 0 dB として読まれる（音量の補正を OUT でしていた場合は、Level で付け直す）。
- **未確認**: 画面での操作（プリセットを切り替えても OUT が動かないこと、Level のノブ）はテストとスクリーンショットまでで、マウス操作では確認していない。Arp Pulse Stab の +1 dB は試聴していない。

## D-057 Init（空の音色）（2026-11-22、ユーザーの依頼）

「空のプリセット、init 的なもの」がほしいという依頼。Factory の音色としてではなく、**ブラウザーの Init ボタン**（`PresetManager::loadInit()`）として作った。

## D-060 Factory の目標を 256 → 128 音色に変更（2026-11-22、ユーザーの指示）

|---|---:|---:|---:|---:|

| Synth Brass | 48 | 18 | 12 | 6 |
| Stab / Chord Hit | 42 | 18 | 16 | 2 |
| Bright Poly | 32 | 12 | 7 | 5 |
| Synth Pluck | 24 | 10 | 7 | 3 |
| Lead / Hook | 16 | 12 | 12 | 0 |
| Bass | 16 | 8 | 7 | 1 |
| Pad / Strings | 12 | 10 | 10 | 0 |
| Octave / Layered | 8 | 4 | 3 | 1 |

- **影響**: コードとテストへの影響はない（目標数はどこにも埋め込んでいない）。`SPEC.md`（v0.18、§11.1 / §17 / §18）、追加仕様 §9 の「総数目標 256」、`README.md`、`CLAUDE.md` ルール 8 の数字、製品ページ（未公開）を書き換えた。これより前の決定（D-042、D-054 など）に出てくる「256」は、当時の記録としてそのまま残す。

## D-065 Simple に TONE（Cutoff / Resonance / Attack / Release）を追加（2026-11-23、ユーザーの指示）

- **決定**: Simple の上段を左右に分け、左に MACROS、右に **TONE** パネルを置く。TONE は Cutoff（`filter.cutoff`）、Resonance（`filter.resonance`）、Attack（`amp.attack`）、Release（`amp.release`）の 4 つのノブ。
- **経緯**: ユーザーの指示「Simple モードで、フィルタをいじれるようにしたい。特にカットオフとレゾナンス」。ほかに足すものを聞かれ、Attack と Release を提案して承認された。音色を選んだあとに直したくなるのは、ほぼ「明るさ・癖・立ち上がり・余韻」の 4 つであるため。
- **入れなかったもの**: Reverb / Delay の量（多くの音色でマクロに割当済みで、ノブが増えすぎる）、Filter の種類や Envelope の量（音色の性格が変わるので Advanced のまま）。
- **実装**: 新しいパラメーターは足していない（140 個のまま）。Advanced の Filter / Amp と同じパラメーターに、ノブをもう 1 つずつつないだだけ。状態・プリセット・オートメーションへの影響はない。ノブは標準の大きさ（Advanced と同じ）で、マクロのノブと中心の高さをそろえた。
- **マクロとの関係**: Cutoff などにマクロが割り当てられている音色では、TONE のノブが基準の値（Base）を決め、マクロがそこからの差分を足す（SPEC §10.2 のとおり）。ノブの表示は基準の値。
- **既知の点**: マクロ名が「Release」の音色（Anthem Saw など）では、MACROS と TONE の両方に「Release」というノブが並ぶ。マクロは音色ごとに複数の設定をまとめて動かすので役割は違うが、名前は重なる。

## D-069 Drive の Mix: 原音と歪ませた音の位相をそろえる（2026-11-23、ユーザーの指示）

- **問題**: Drive は 4 倍のオーバーサンプリングで処理する。歪ませた音は IIR ハーフバンドフィルター 4 段を通るぶん数サンプル遅れる（遅れは周波数によって違う）。Mix はそこへ、遅れのない原音をそのまま混ぜていた。Mix が 100 % 未満だと、高域で 2 つの音が打ち消し合う。
- **測定**（48 kHz、Drive 0 %・小さい入力のほぼ線形な条件、Mix 50 %）:

| 周波数 | 修正前 | 修正後 |
|---|---:|---:|
| 1 kHz | −0.43 dB | 0.00 dB |
| 2 kHz | −1.89 dB | −0.01 dB |
| 3 kHz | −4.80 dB | −0.03 dB |
| 4 kHz | −10.89 dB | −0.05 dB |
| 5 kHz | **−28.52 dB** | −0.07 dB |
| 6 kHz | −8.93 dB | −0.11 dB |
| 8 kHz | −1.37 dB | −0.18 dB |

## D-076 ホスト（DAW）のキー操作を横取りしない（2026-11-23、ユーザーの質問から）

- **経緯**: ユーザーの質問「DAW 上で使う時にキー操作を横取りしたりしない？」。D-068 の調査で挙がっていたが、ホスト依存で確かめられないことを理由に見送っていた。JUCE のソースで、何が起きるかを確かめた。
- **直す前に起きていたこと**:
  - ボタンやスイッチを押したあと: Return で、そのボタンがもう一度押される（JUCE のボタンは既定でキーボードフォーカスを受け取り、Return を処理する）。
  - 選択欄を選んだあと: 矢印キーで選択が切り替わり、Return で一覧が開く。
  - 文字の入力欄（検索、Save As、マクロ名）を使ったあと: カーソルが残り、スペースキー（再生 / 停止）なども文字として入力される。
  - ノブとスライダーは、JUCE の既定でフォーカスを受け取らない。どの部品も処理しなかったキーは、JUCE がホストへ渡す。
- **決定**: キーを受け取ってよいのは、文字の入力欄だけにする。
  - エディターが、フォーカスの移動の通知（`juce::FocusChangeListener`）を受ける。自分の画面の中で、入力欄でも「受け皿」でもない部品がフォーカスを受け取ったら、すぐに受け皿（エディターの中身のコンポーネント）へ移す。受け皿はキーを処理しないので、キーはホストへ渡る。
  - 入力欄は、Esc、および 1 行の欄の Return で、フォーカスを手放す。入力欄の外をクリックしたときは、クリックされた部品 → 受け皿の順でフォーカスが移り、入力欄から外れる。
  - ノブの数値入力と、編集できる選択欄（Save As の Category）の入力欄も、入力欄として扱う（入力中はキーを受け取り、確定すると手放す）。
- **採らなかった方法**: 部品ごとに「フォーカスを受け取らない」と設定する方法。最初にこの方法で実装したが、自動テストが取りこぼしを見つけた。JUCE は、有効 / 無効の切り替えのたびにその設定を元に戻す（ノブの数値表示のラベル、選択欄）。表示していないタブの部品は画面の階層にいないので、設定が届かない。
- **変わらないこと**: 選択欄のメニューを開いている間の矢印キーと Return（メニューは別のウインドウで、この仕組みの対象外）。Tab キーは JUCE がフォーカスの移動に使うので、ホストへは渡らない（以前から）。
- **テスト**（`tests/ui/KeyboardFocusTests.cpp`。画面まわりで初めての自動テスト）: VST3 / AU / Standalone のそれぞれで、Simple・Advanced の全タブ・ブラウザーの全部品について、「入力欄と受け皿以外は受け皿へ移す」「入力欄は移さない」「入力欄は Esc / Return で手放す配線がある」ことを確かめる。
- **自動テストで確かめられないこと**: 実際のウインドウでフォーカスが移ること（Desktop からの通知は、画面のないテストでは起きない）。Standalone での確認と、DAW でのキー操作の確認が要る。
